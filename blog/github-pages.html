使用 GitHub Pages 免费部署前端项目

2025年6月6日 · 阅读需 6 分钟
Mono
全栈开发者 | 开源爱好者 | Minecraft 模组作者

GitHub Pages 是 GitHub 提供的免费静态网站托管服务，非常适合个人博客、项目文档、作品集展示。本文覆盖从零部署到自定义域名的完整流程。

一、GitHub Pages 是什么​

GitHub Pages 从仓库的特定分支或目录读取静态文件，并通过 github.io 子域名提供服务。

核心优势：

  • 🆓 完全免费：无流量限制、无带宽收费
  • 🔒 自动 HTTPS：SSL 证书自动签发和续期
  • ⚡ 全球 CDN：Fastly CDN 加速
  • 🔄 CI/CD 集成：配合 GitHub Actions 自动构建部署
  • 🌐 自定义域名：支持绑定自己的域名

适用场景：

场景推荐方案
个人博客Docusaurus / Hexo / Hugo → GitHub Pages
项目文档Docusaurus / VitePress → GitHub Pages
单页应用 (SPA)React / Vue → GitHub Pages
作品集纯 HTML/CSS/JS → GitHub Pages

二、部署方式对比​

GitHub Pages 支持两种部署源：

方式一：分支部署（传统）​

直接推送 HTML/CSS/JS 到 gh-pages 分支：

# 构建项目
npm run build

# 将 build 产物推送到 gh-pages 分支
npx gh-pages -d build

适合：快速原型、个人尝试

方式二：GitHub Actions（推荐）​

推送源码，由 Actions 自动构建和部署：

# 源码推送到 main 分支
git push origin main
# → GitHub Actions 自动构建
# → 产物自动部署到 gh-pages 分支

适合：正式项目、团队协作

三、使用 GitHub Actions 自动部署​

3.1 Docusaurus 项目​

.github/workflows/deploy.yml
name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Setup pnpm
        uses: pnpm/action-setup@v2
        with:
          version: 8

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build
        run: pnpm build
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}

      - name: Setup Pages
        uses: actions/configure-pages@v4

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./build

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

3.2 Create React App 项目​

.github/workflows/deploy.yml
# ...（同样的 checkout / setup-node / install 步骤）

      - name: Build
        run: npm run build

      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./build

3.3 Vite + React 项目​

      - name: Build
        run: npm run build

      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
          cname: monoblog.cc.cd    # 自定义域名（可选）

四、配置 Secrets​

在 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret 中添加密钥：

Secret 名称说明
SUPABASE_URLSupabase 项目 URL
SUPABASE_ANON_KEYSupabase 匿名密钥
VITE_API_KEY其他 API 密钥（构建时注入）

⚠️ 切勿将密钥直接写在代码中！所有敏感信息都应通过 Secrets 配置。

五、GitHub Pages 设置​

5.1 启用 Pages​

  1. 进入仓库 → Settings → Pages
  2. Source：选择 GitHub Actions
  3. 等待 Actions 运行完成后自动部署

5.2 选择分支部署（方式一）​

如果不使用 Actions：

  1. Source：选择 Deploy from a branch
  2. Branch：选择 gh-pages → / (root) → Save

5.3 查看部署状态​

  • 仓库 → Actions 标签页查看构建日志
  • 仓库 → Settings → Pages 查看部署 URL
  • 每次推送后 GitHub 会自动触发构建

六、自定义域名​

6.1 添加域名​

在 GitHub Pages 设置页面的 Custom domain 中输入你的域名，如 monoblog.cc.cd。

6.2 DNS 配置​

在你的域名 DNS 管理面板中添加以下记录：

使用子域名（推荐）：

类型名称值
CNAMEwww你的用户名.github.io

使用 apex 域名（裸域）：

类型名称值
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153

6.3 验证域名​

添加 DNS 记录后，回到 GitHub Pages 设置页面，点击 Save。GitHub 会自动验证 DNS 并签发 SSL 证书（约需 5-30 分钟）。

6.4 保留 CNAME 文件​

如果用 Actions 部署，在构建产物中包含 CNAME 文件：

docusaurus.config.js
// Docusaurus 插件自动生成 CNAME
function AutoGenerateCNAMEPlugin() {
  return {
    name: "auto-generate-cname",
    async postBuild({ outDir }) {
      const cnameFilePath = path.join(outDir, "CNAME");
      fs.writeFileSync(cnameFilePath, "monoblog.cc.cd", "utf8");
    },
  };
}

或者直接在 static/ 目录下放一个 CNAME 文件。

七、SPA 路由问题的处理​

GitHub Pages 不支持客户端路由，直接访问 /about 会返回 404。

解决方案一：Hash 路由​

// React Router
import { HashRouter } from 'react-router-dom';

root.render(
  <HashRouter>
    <App />
  </HashRouter>
);

URL 变为 example.com/#/about，不再产生 404。

解决方案二：404.html 重定向​

在 public/404.html 中放置重定向脚本：

<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Redirecting...</title>
  <script>
    sessionStorage.redirect = location.href;
  </script>
  <meta http-equiv="refresh" content="0;URL='/'">
</head>
</html>

配合在 index.html 中恢复路径。但此方案对 SEO 不友好。

解决方案三：使用 Vercel / Netlify​

如果 SPA 路由是刚需，建议直接使用 Vercel（后续章节详细介绍）。

八、GitHub Pages vs Vercel 对比​

特性GitHub PagesVercel
价格免费免费（有额度）
构建Actions 配置零配置自动检测
路由不支持 SPA 路由原生支持
Serverless不支持支持 Edge Functions
预览部署手动自动（每个 PR）
域名绑定支持支持
SSL自动（Let's Encrypt）自动
缓存Fastly CDNVercel Edge Network
环境变量Actions Secrets项目面板配置

选择建议：

  • 纯静态文档/博客 → GitHub Pages 足够
  • 需要 API Routes / Serverless → Vercel
  • 需要预览部署和团队协作 → Vercel

九、常见问题​

9.1 部署后页面空白​

检查 package.json 中的 homepage 字段：

{
  "homepage": "https://ye2f4.github.io/my-app"
}

或者在 Vite 中配置 base：

vite.config.ts
export default defineConfig({
  base: '/my-app/',
});

9.2 资源 404​

确保所有静态资源路径使用相对路径，或在构建工具中配置正确的 publicPath。

9.3 Docusaurus baseUrl​

docusaurus.config.js
const config = {
  baseUrl: '/',        // 自定义域名
  // baseUrl: '/repo/', // GitHub Pages 子路径
};

9.4 Actions 构建超时​

检查是否有循环依赖或过大依赖。GitHub Actions 免费额度：2000 分钟/月（公开仓库免费）。

总结​

GitHub Pages 是个人开发者最友好的免费部署方案：

  1. 创建 .github/workflows/deploy.yml 配置文件
  2. 设置 Secrets 存储敏感信息
  3. 开启 Pages → 选择 Actions 部署
  4. 添加 CNAME 记录 绑定自定义域名
  5. 推送代码 → 自动构建部署

整个流程配置一次后永久自动运行，真正实现"推送即上线"。
